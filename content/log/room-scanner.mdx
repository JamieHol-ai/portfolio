## Approach

PLACEHOLDER COPY. <PH>PLACEHOLDER — the sweep pattern, timing, and the serial protocol back to the host.</PH>

The sensor returns a distance along a known bearing, so each sample is a point
in spherical coordinates about the scanner: pan angle, tilt angle, range. Turning
that into a Cartesian point cloud is a coordinate transform. Turning it into a
*good* point cloud is everything else — the calibration between commanded servo
angle and actual bearing, the settle time before a reading is trustworthy, and
what to do with the returns that are simply wrong.

## What I'd change

PLACEHOLDER COPY. <PH>PLACEHOLDER — what I would do differently.</PH>

Looking back at it from the LiDAR work: this is the same problem with the
scanning done in software and the vehicle held still. The thing it taught me
that transferred directly is that a range sensor's error model is not a single
number — it depends on the surface and the incidence angle, and a pipeline that
treats every return as equally good will produce a cloud that looks plausible
and measures badly.
